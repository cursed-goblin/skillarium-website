Where the applications live

Every application, enquiry and resume from this website lands in one Google Sheet and one Drive folder. There is no separate dashboard to log into and no password to lose — access is controlled by who you share the Sheet with.

Applications sheet

Students and teachers arrive on the Applications tab, newest at the bottom, each with a reference number. Enquiries from the contact form sit on Leads.

Open the sheet →

Resumes

Every uploaded resume is saved to a private Drive folder named Skillarium Resumes and linked from the resume_url column of the row it belongs to.

Only people you explicitly share that folder with can open the files.

Handling an application

  1. 01

    Read the row

    Open the Applications tab. The columns follow the form: contact details first, then the student or teacher specific answers, then their message and resume link.

  2. 02

    Change the status

    Edit the status cell to one of: new, shortlisted, interview, accepted, rejected, withdrawn. That is exactly what the applicant sees on the Check Status page.

  3. 03

    Tell them

    With the row selected, use the Skillarium → Email applicant about current status menu inside the Sheet. It sends a written update for that status and stamps the row as updated.

  4. 04

    Keep notes

    Use the Notes tab for anything said on a call. Put the reference number in the first column so the history stays searchable.

Editing what the website shows

The site reads its content from the same sheet, so you do not need a developer to change a fee or add a batch.

Courses

The Courses tab drives the course catalogue. Set is_published to yes to show a course, and separate outcomes with a | character.

Faculty

The Faculty tab drives the faculty page. Add a photo URL and set is_published to yes. Placeholder rows should be replaced before launch.

Batches

The Batches tab drives the fees and batch dates page. Update seats_left as enrolments come in and set status to open, filling or closed.

Changes appear on the website the next time a visitor loads the page. Nothing needs redeploying.
